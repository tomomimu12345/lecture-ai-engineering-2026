# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 素のLLM は、問題文だけを見てその場で推測して回答するので、講義の用語や定義を抑えられず、一般的な回答をしてしまう。
  - エージェントは `search_glossary` で用語集を確認し、必要に応じて `get_lecture_summary` で回の要点を参照してから回答するため、講座に沿った説明ができる。
  - その結果、単なる一般知識ではなく教材・用語に対応した回答になった。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 例: `[tool call] search_glossary({'query': 'LoRA'})`
  - 例: `[tool call] get_lecture_summary({'lecture': 2})`
  - 例: `[tool call] make_quiz({'lecture': 2})`
  - モデルが質問の意図を理解して、必要なツールを選んで呼び出していることが確認できた。

- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 実際の処理は、ツール選定のためのモデル呼び出しと、ツール結果を踏まえて最終回答を作るモデル呼び出しの2段階が中心になる。
  - そのため、1つの質問に対して「複数回の内部リクエスト」が発生し、`result.usage` で確認できる。今回は「ツールを使って最終回答を組み立てる」構成であることがわかった。

- 追加したツールと、docstring に書いた説明：
  - 追加したツール: `make_quiz(lecture: int) -> str`
  - docstring: `確認問題を出したいときに、指定した回の用語から1問を選んで返す。`
  - これにより、モデルは「確認問題を出したいときは make_quiz を使う」と判断しやすくなり、講義の確認問題生成ができるようになった。

- 結果：
  - ADK版、Pydantic AI版のどちらも用語集に基づき、「基礎・実装・発展の3段階で、どれか1つに取り組めばよい」と回答した。同じ質問を各版で2回試したところ、1回目は補足の量に差があったが、2回目は説明の内容や詳しさもほぼ同じで、主な違いは言い回しや文章の構成だった。
- 気づき・疑問：
  - Pydantic AI版は `agent.tool_plain(...)` でツールを登録するのに対し、ADK版は `Agent(..., tools=[...])` にツール一覧を渡してエージェントを組み立てる。指示とツールを共通化しても、フレームワークごとにエージェントの構成方法が異なることが分かった。
  - モデルに渡す指示を比較した。Pydantic AI版の `TestModel` で確認した `instruction_parts` は、ソースに書いた `INSTRUCTIONS` と同じ次の内容だった。

    ```text
    あなたはAIエンジニアリング講座（AIE2026）の学習支援エージェントです。
    - 用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。
    - 回の内容を聞かれたら get_lecture_summary を使う。
    - 用語集に見つからないことは、推測で断定せず「用語集にはない」と伝える。
    - 回答の最後に、関係する回（第N回）を示す。
    - 宿題の答えそのものは書かず、考え方のヒントで導く。
    ```

    ADK版は `before_model_callback` で取得した `LlmRequest.system_instruction` に、上記と同じ指示に加えて次の文が含まれていた。

    ```text
    You are an agent. Your internal name is "glossary_agent".
    ```
  - このため、実効的な指示とツール一覧には具体的な差があり、ハーネスの違いが回答に影響した可能性がある。ただし、回答の違いがこの差によるものか、生成ごとの揺れによるものかは、今回の比較だけでは特定できなかった。

- 追加で取り組んだレベル：発展（b・システムプロンプトの比較）
- やったこと：
  - `pi --version` で Pi 1.5.0 が利用できることを確認し、公開リポジトリの `packages/coding-agent/src/core/system-prompt.ts` を読んで、AIE2026 の `INSTRUCTIONS` と比較した。
- 結果：
  - Pi の既定システムプロンプトは、ファイルを調べ、コマンドを実行し、コードを変更するコーディングアシスタントとしてタスクを進める方針になっている。既定のツールは `read`、`bash`、`edit`、`write` で、簡潔な回答やファイルパスの明示も促している。
  - AIE2026 の `INSTRUCTIONS` は、用語集や講義要約を参照して質問に答え、用語集にない内容を断定せず、関連する回を示し、宿題では答えでなくヒントを返すよう指示している。
- 気づき・疑問：
  - Pi はツールを使って作業環境やコードを変更するタスク向けであるのに対し、AIE2026 のエージェントは教材を根拠に説明し、学習を支援するタスク向けだと分かった。Pi の既定プロンプトには講座固有の用語確認や宿題のヒントの指示はなく、AIE2026 の `INSTRUCTIONS` にもファイル編集やコマンド実行の手順はない。
