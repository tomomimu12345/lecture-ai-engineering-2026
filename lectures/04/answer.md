## 宿題

- 取り組んだレベル：発展
- やったこと：SWE-bench Verified を選び、Hugging Face の評価セットから Astropy の課題を4件読みました。
  - `astropy__astropy-12907`：入れ子になった複合モデルで、入力と出力の独立性を表す行列が誤って計算される問題。モデルの組み合わせ方と行列計算の理解が必要です。
  - `astropy__astropy-13033`：必須列が複数ある場合、列を削除したときのエラーメッセージが誤解を招く問題。実際に不足した列を適切に示す必要があります。
  - `astropy__astropy-13236`：構造化 NumPy 配列を自動的に `NdarrayMixin` に変換する既存動作を見直す提案。通常の `Column` で扱えるようになった後の互換性を確認する課題です。
  - `astropy__astropy-13453`：HTML 形式で表を書き出すと、指定した列の表示形式が反映されない問題。出力処理とフォーマット設定の連携を調べる必要があります。
- 作成・検証方法：元の SWE-bench は、12の Python リポジトリにある GitHub issue と対応する pull request から作られた2,294件の課題です。SWE-bench Verified は、その候補を93人の開発者が各課題3人で独立に確認し、問題文の明確さ、テストの境界ケースの網羅性・安定性、修正による回帰の有無、難易度などを確認して選んだ500件です（候補1,699件を確認）。出典：[SWE-bench論文](https://arxiv.org/abs/2310.06770)、[OpenAIの選定説明](https://openai.com/index/introducing-swe-bench-verified/)。
- 今日の評価セットとの違い：今日のセットは講師1人が作った質問・回答10件を、人とLLMが rubric に沿って採点します。SWE-bench Verified は実際のリポジトリの修正課題500件を扱い、修正パッチをテストで評価します。実際の開発に近く、テストで自動採点できる一方、リポジトリ環境の準備やテスト実行が必要で、テスト自体の品質にも結果が左右されます。
- 結果・気づき：「Verified」は人手で確認した500件のデータセットという意味で、全課題が誤りなく採点できる保証ではありませんでした。テストの想定漏れや厳しすぎる条件は、人の確認を通過しても残ることがあります。Epoch AI の2026年レビューによると、OpenAIが監査した138件で59.4%に、正しい修正を誤って不合格にするテスト上の問題が見つかりました。評価セットは作った後も検証し続ける必要があると感じました。
